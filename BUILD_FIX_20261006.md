# Windows build fix — 2026-10-06

## What failed

The previous `build_windows.bat` used both:

```text
--specpath build\spec
--icon assets\cancheria.ico
```

PyInstaller stored the relative icon path in the generated spec and later resolved it from `build\spec`, effectively looking for:

```text
build\spec\assets\cancheria.ico
```

That path does not exist.

## Fix

The new build passes an absolute icon path:

```text
%ROOT%\assets\cancheria.ico
```

Both executables are still written directly in the CANCHERIA root with:

```text
--distpath "."
```

## Build isolation

The old command used broad `--collect-all` flags while running against the global Python environment. On a machine that also had Torch, ONNX Runtime, Pandas, SciPy and other packages installed, PyInstaller inspected them and surfaced an unrelated NumPy/ONNX compatibility error.

The new script creates `.build-venv` and installs only CANCHERIA's declared dependencies plus PyInstaller. It uses explicit dependency anchors for the packages needed by the frozen WPSetter worker instead of collecting every OpenAI/Playwright submodule.

## Expected result

After running `build_windows.bat`:

```text
CANCHERIA/
├── cancheria.exe
├── configurador_cancheria.exe
└── release/
    └── CANCHERIA_WINDOWS.zip
```

The `dist/` folder is not used as the final executable location.
